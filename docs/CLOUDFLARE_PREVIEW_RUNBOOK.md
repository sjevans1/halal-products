| Field | Value |

| Application | `Tayyib Halal Preview` |
| Domains covered | `tayyib-halal-preview.pages.dev` and `*.tayyib-halal-preview.pages.dev` |
| Policies | (1) allow the owner email address; (2) non-identity service token for automated checks |
| Session duration | 24h |

The wildcard covers branch aliases and immutable deployment URLs, so no preview
hostname is reachable without authentication. Unauthenticated requests receive a
302 redirect to the Access login page; invalid service-token credentials receive
401. Scripted checks send service-token headers from a file kept outside the
repository (`~/.config/tayyib-preview/access.env`, mode 0600, operator machine).

Application controls remain behind Access: every private API verifies a signed
Access JWT against the exact application audience and an allowlist, and every
operator, trust, editorial, and steward endpoint answers 503 while its
activation flag is off. Hiding routes and `noindex` are presentation details,
not the security boundary.

## Deploy a preview

### Manual (operator machine)

```bash
cd ~/halal-products
git checkout <branch>
set -a; . ~/.config/workspace-ci-orchestrator/cloudflare.env; set +a
export CLOUDFLARE_API_TOKEN="$CF_API_TOKEN"
npm run check
wrangler pages deploy public \
  --project-name tayyib-halal-preview \
  --branch "$(git branch --show-current)"
```

### Automated (GitHub Actions)

`.github/workflows/preview.yml` runs on every push to a branch other than
`main`. After `npm run check` passes it builds and deploys that branch as a
preview. It cannot deploy production. A manual dispatch is available from the
Actions tab once the workflow exists on the default branch.

Production publishing remains a deliberate owner decision: merge the approved
stack, then deploy from `main` through the Cloudflare dashboard or
`wrangler pages deploy public --project-name tayyib-halal-preview --branch main`.

## Rollback

- Fastest: Cloudflare dashboard, Workers & Pages, `tayyib-halal-preview`,
  Deployments, roll back to the previous deployment. Instant, no git change.
- Repository view: check out the last accepted commit and redeploy with the
  manual command above. Leave the branch itself intact for review.
- If Access itself is misconfigured, repair or recreate the application using
  the table above. Removing the application would return the preview to public
  reachability, so treat that as an incident action.

## Troubleshooting

- `403 error code 1010` from scripted requests: Cloudflare bot management
  rejects non-browser user agents before Access runs. Send a browser-like
  `User-Agent` together with the service-token headers.
- TLS handshake failure on a brand-new deployment URL: the wildcard certificate
  for `*.tayyib-halal-preview.pages.dev` is still provisioning. Wait a few
  minutes and retry.
- Unauthenticated probes get a 302 to the login page: that is the protection
  working. Send service-token headers for scripted checks.
- Preview URLs are `noindex` by design. SEO scoring applies only to an approved
  production domain.
- `wrangler pages deploy` refuses a dirty working tree. Commit or clean first,
  or pass `--commit-dirty=true` when the dirty state is intentional.

## Secrets and credentials

- No credential is committed to the repository.
- Local copies live at `~/.config/tayyib-preview/access.env` (Access service
  token) and `~/.config/workspace-ci-orchestrator/cloudflare.env` (account API
  token), mode 0600, operator machine only.
- GitHub Actions reads repository secrets `CLOUDFLARE_API_TOKEN` and
  `CLOUDFLARE_ACCOUNT_ID`.
- Recommended rotation: create a scoped token (My Profile, API Tokens, Create
  Token, Custom: Account, Cloudflare Pages: Edit), set it as
  `CLOUDFLARE_API_TOKEN` with `gh secret set CLOUDFLARE_API_TOKEN`, and retire
  the broader account token once no other pipeline needs it.
